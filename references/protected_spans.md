# 원문 보호 구간 판정과 검증

교정 전에 문맥으로 보호 대상을 식별한다. `protected_spans`는 **원문의 위치와 사유를 기록한 목록**이며, 따옴표나 영문 여부만으로 만드는 목록이 아니다. 이 원칙은 HWPX·DOCX·Markdown 및 다른 입력 형식에 동일하게 적용한다.

## 무엇을 보호하는가

| 대상 | 처리 | 예외·구분 |
|---|---|---|
| 면담 참여자 발화 (`interview`) | 구어체·비문·오타까지 원문 유지 | 인용부호 없는 발화도 포함. 연구자의 해설은 따로 교정 |
| 출처의 직접 인용 (`quotation`) | 인용 내용 원문 유지 | 짧은 구절·80자 초과·영문·여러 문단 인용도 포함. 인용부호와 출처 표기 등 바깥 형식은 별도 교정 가능 |
| 시행된 설문·기존 척도 문항 (`survey`) | 문항 내용 원문 유지 | 저자가 새로 만드는 미시행 문항이고 문항 개선을 요청했다면 수정 제안 가능. 기존 도구를 인용한 문항과 구분 |
| 공식 명칭 (`official_name`) | 확인된 법령·기관·사업·도구의 명칭 유지 | 의심되는 표기는 원문 확인 사항으로 남김. 강조·가칭·작업용 용어를 공식 명칭으로 간주하지 않음 |
| 통계 표현 (`statistics`) | 변수·값·부호·비교 연산자·단위·대응 관계 유지 | 기계 검사는 전체 표현의 토큰이 같을 때 공백 정리만 허용. 반올림, 소수점 앞 0 추가, 변수명 변경 등은 별도 확인 없이 반영하지 않음 |
| 사용자 지정 용어 (`user_term`) | `protected_terms`의 문자열이 등장하는 모든 위치에서 그대로 유지 | 완전 일치 문자열 기준. 임의로 유사어·어간까지 확대하지 않음 |
| 원문 여부가 불명확한 구간 (`uncertain`) | 임시 보호하고 `원문 확인 필요`로 기록 | 인용인지 강조인지, 기존 문항인지 새 초안인지 불분명할 때 해당 구간만 보류 |

**영문 초록·키워드는 영문이라는 이유만으로 동결하지 않는다.** 한국어 전용 교정 규칙을 적용하지 않으며, 영어 교정이 요청된 범위에서 문법·표현을 점검한다. 그 안의 직접 인용·공식 명칭·수치 등은 위 원칙대로 보호한다. 따옴표 안이라도 저자가 강조한 일반 표현이면 교정할 수 있다.

보호 구간의 오타처럼 보이는 부분도 자동 수정하지 않는다. 교정교열표나 요약 리포트에 위치·원문·보호 사유와 확인할 내용을 남긴다. 사용자가 원전 확인 결과에 따라 특정 수정을 지시하면 그 구간의 기록과 수정안을 함께 갱신한다. 보호 위반을 통과시키려고 목록을 비우거나 `allow_loss`를 추가하지 않는다.

## 기록 방법

1. 원고를 교정하기 전 문단·표 셀에 고정 `pid`를 부여한 `WORK/paras.json`을 준비한다. HWPX는 `hwpx_revise.py extract`의 결과를 사용한다. DOCX·Markdown 등은 추출한 원문을 바꾸지 않은 상태로 문단별 `text`를 기록하고, 그 추출본의 SHA-256을 `source_hash`에 넣는다. `작업정보.md`의 입력 파일 SHA-256과 구분한다.
2. `WORK/protection.json`에 `source_hash`, `protected_spans`, `protected_terms`를 기록한다. 각 구간에는 `pid`, `start`, `end`, `text`, `kind`, `reason`을 둔다. 보호할 구간이 없다는 검토를 마쳤으면 `protected_spans: []`를 명시한다.
3. 좌표는 **원본 문단 문자열의 0부터 시작하는 Python 문자 인덱스, 끝 제외**다. 바이트·UTF-16 인덱스와 혼용하지 않는다. `text == paragraph[start:end]`를 확인한다. 여러 문단에 걸친 인용은 각 문단의 해당 부분을 기록한다. 인용부호 밖 해설까지 보호하지 않는다.
4. 사용자 지정 용어는 `protected_terms`에 넣으면 검사 도구가 모든 등장 위치를 보호한다. 나머지 구간은 문맥을 보고 식별해야 하며 도구가 자동 탐지하지 않는다.
5. 자동 반영할 `edits`와 보호 기록을 합쳐 `WORK/edits.json`을 만든다. 모든 `old`와 보호 좌표는 같은 원본 추출본을 기준으로 한다. 원본이 바뀌면 재추출·재식별한다.

예를 들어 원본 문단이 `참여자는 “솔직히 되게 막막했어요.”라고 말했다.`이면:

```json
{
  "source_hash": "<paras.json의 source_hash>",
  "protected_spans": [
    {"pid": 0, "start": 6, "end": 19, "text": "솔직히 되게 막막했어요.",
     "kind": "interview", "reason": "면담 참여자의 실제 발화"}
  ],
  "protected_terms": [],
  "edits": [{"pid": 0, "old": "말했다", "new": "진술했다"}]
}
```

보호 구간 밖의 해설만 바꾸는 예시다. 교체 지시는 보호 구간과 겹치지 않게 좁힌다. **보호 내용을 그대로 포함하더라도 문장 전체를 교체하는 지시는 거부**하므로 바깥 부분만 나누어 제시한다. 통계 구간은 구간 내부의 수정들을 합친 뒤 토큰을 비교하므로 공백 조정은 가능하다.

## 적용과 출력 대조

모든 형식에서 자동 반영 전에 다음 검사를 수행한다:

```bash
python3 "<스킬 폴더>/scripts/protected_spans.py" "$WORK/paras.json" "$WORK/edits.json"
```

- HWPX의 `apply`는 같은 검사를 내장하며 위반 시 **파일을 쓰기 전에** 중단한다. `--force`나 `allow_loss`도 보호 위반을 허용하지 않는다. 실제 XML 편집 결과가 검사를 통과한 교체 지시와 일치하는지도 저장 전에 대조한다.
- DOCX·Markdown은 통과한 수정만 반영하고, 결과를 다시 읽어 보호 원문이 해당 위치에서 유지되는지 대조한다. 수정으로 좌표가 이동하므로 원본 좌표를 결과 문자열에 그대로 사용하지 않는다. DOCX의 표·서식·수정 추적은 해당 편집 도구에서 별도 확인한다.
- Python을 사용할 수 없으면 같은 기준으로 원문과 후보안을 대조하되 자동 검증을 수행했다고 쓰지 않는다. 보호 여부나 원문 일치를 확인할 수 없는 수정은 제안만 남긴다.

구형 HWPX 교정 지시에 `protected_spans`가 없으면 기존의 짧은 `「…」`·`“…”` 소실 검사도 유지한다. 이것은 전체 원문 보호를 대신하지 못한다. 현행 스킬은 항상 구간 검토 결과를 전달한다. 독립 `hwpx_revise.py verify`는 보호 기록을 받지 않으므로 전체 보호 검사가 아니라 기존 구조·소실 검사다.

## 예제 검증

실행 가능한 사례는 [examples/protected-spans.json](../examples/protected-spans.json)에 있다. 각 사례는 원문·문맥·보호 주석·수정 후보·허용 여부를 포함한다.

```bash
python3 -m unittest discover -s tests -v
```

면담·긴 인용·설문 원문·공식 명칭·사용자 지정 용어·통계 값/부호 변경은 차단하고, 보호 밖 해설·강조용 따옴표의 오타·요청된 영문 교정·통계 공백 정리는 허용하는지 검사한다. 같은 사례를 공통 검사기와 합성 HWPX에 적용해 실제 출력과 저장 전 차단 여부를 확인한다. 이 검사는 **주어진 보호 주석과 수정 후보에 대한 검사**이며, 모델의 보호 구간 탐지 정확도나 실제 한글 앱의 렌더 품질을 측정하지 않는다.
